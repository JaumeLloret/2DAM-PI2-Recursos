# Objetivos, IN/OUT y aceptación
## Método
1. Localiza una necesidad y fuente. Distingue observación de preferencia.
2. Escribe beneficiario + mejora + resultado observable.
3. Delimita resultados IN y exclusiones OUT con razón.
4. Contrasta obligaciones y condiciones de viabilidad.
5. Une con tareas del catálogo auténtico cuando esté disponible.
6. Define situación, acción, resultado, excepción y evidencia.
7. Revisa contradicciones antes de negociar.

No confundas objetivo, especificación y tarea. «Usar Flutter» es una condición tecnológica del cliente, no una necesidad ni un criterio de aceptación suficiente. Un objetivo puede apoyarse en varias tareas; una tarea puede ayudar a varios objetivos sin multiplicar AT.

## Ejemplo guiado distinto de TRAIN
Archivo vecinal: el personal no sabe si un ejemplar sigue prestado.
- Necesidad ficticia: resolver estado de préstamo sin consultar copias contradictorias.
- Objetivo: que personal autorizado localice el préstamo vigente de un ejemplar y pueda reconocer su cierre.
- IN: consulta y devolución conservando historial.
- OUT: préstamo entre sedes, porque el caso solo acredita una sede.
- Aceptación: dado préstamo abierto, confirmar devolución muestra cierre y disponibilidad; repetir no duplica cierre ni elimina historial.
- Evidencia prevista: muestra antes/después y repetición, saneada, cuando exista el flujo.

No aparecen IDs/AT reales. El ejemplo enseña el razonamiento y no resuelve el caso ReservaLab.

## Criterios fuertes y débiles
| Débil | Problema | Reescritura |
|---|---|---|
| «Aplicación moderna» | No identifica mejora | Resultado útil para un actor y escenario |
| «Que funcione» | No delimita observación | Situación/acción/resultado verificable |
| «Sin errores» | Promesa absoluta | Excepción relevante y respuesta esperada |
| «Exportar todo» | Ámbito y acceso indefinidos | Información, formato y perfil autorizados |
| «Lo hará otro módulo» | Supone disponibilidad | Dependencia y condición comprobable |

Una exclusión legítima recorta una opción sin negar obligaciones. Una exclusión ilegítima elimina el núcleo para cuadrar una suma. «Pendiente de PI3» describe planificación posterior, no una función OUT.

## Transferencia
En E03 redacta 3–5 objetivos desde E02. En E06 desarrolla al menos tres resultados con caso positivo y límite. Comprueba objetivo → IN → referencia auténtica o PENDIENTE_CATALOGO → aceptación → evidencia prevista. No rellenes un ID ficticio para cerrar la cadena visualmente.

En negociación conserva qué cambió, por qué y qué documentos se revisan. Después de una baseline confirmada, CR prospectivo. El contrato preparado no constituye planificación detallada.
